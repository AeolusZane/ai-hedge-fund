Chapter 03

第一次，它猜错了

Agent 找到了 NullPointer 的位置，但修复方式是「在调用处加 if 判空」。

AGENT 的修复
// UserService.java:142 public void validateSession(UserSession s) { + if (s != null && s.getToken() != null) { + tokenStore.verify(s.getToken()); + } }
小林的评价
方向对了，但治标不治本
根因不在调用处——是上游 LoginController 没有传参数。应该在方法入口做参数校验，而不是在每个调用点加 if。

反馈
根因不在调用处，而在上游参数缺失。应该在方法入口做参数校验，而不是在每个调用点加 if。这种模式在项目中很常见，Agent 应该学会从根因层面修复。
难度：中等 类型：NullPointer 引导标签：参数校验
💡 这段反馈会被 Agent 记住，影响它未来处理类似 Bug 的方式。

Learning

Agent 记住了

结合小林的反馈，Agent 提炼出一条可复用的经验。

经验 #001
已验证
"当 NullPointer 出现在深层调用链时，优先检查方法入口的参数校验，而非在调用点逐个判空。这是「防御性编程」的核心原则——在边界处拦截异常。"
